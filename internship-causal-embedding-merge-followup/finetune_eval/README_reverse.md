# finetune_eval — Reverse-Direction Finetuning

Fine-tunes the same BERT bi-encoder on each dataset but with **the reverse pair as the sole hard negative**, then evaluates whether the model can distinguish the forward direction (`a→b`) from the reverse direction (`b→a`).

Same 5 datasets as the standard pipeline: `aep_causal`, `followupqg`, `multiwoz_v24`, `qrecc`, `workflow`.

---

## The idea: reverse direction as hard negative

Standard finetuning (in `results/`) uses 4 semantically similar but wrong positives as hard negatives — it teaches *topical discrimination*.

This variant teaches *directional discrimination*:

```
For every pair (anchor=x, positive=y):

    Training signal:
        maximize  sim( enc_anchor(x), enc_positive(y) )   ← forward, label 1
        minimize  sim( enc_anchor(x), enc_positive(x) )   ← reverse, label 0
                                            ↑
                              anchor text fed into the POSITIVE tower
                              = the b→a direction
```

K=1 hard negative per anchor (instead of K=4). No kNN mining needed — the hard negative is simply the anchor text itself.

---

## Is the test set set up the same way? ✓ Yes

Training pairs and test pairs are generated by the same script (`mine_hard_negatives_reverse.py`) with the same rule: `hard_neg = anchor`.

| dataset | train pairs | test pairs | hard_neg rule |
|---|---|---|---|
| aep_causal | 5,487 | 562 | hard_neg = anchor text |
| followupqg | 2,790 | 501 | hard_neg = anchor text |
| multiwoz_v24 | 15,000 (capped) | 7,368 | hard_neg = anchor text |
| qrecc | 15,000 (capped) | 5,204 | hard_neg = anchor text |
| workflow | 20,000 (capped) | 260,487 | hard_neg = anchor text |

The evaluation script (`evaluate_finetune_reverse.py`) independently recomputes `enc_positive(x)` at test time from `data_6/<dataset>/test.jsonl` — it does not read `test_pairs.jsonl`. Both paths produce the same 2-candidate setup, confirming consistency.

*Note: `aep_causal` raw test file has 563 lines, 1 has an empty field and is filtered by `load_pairs` → 562 usable pairs, consistent between train-time mining and eval-time loading.*

---

## Evaluation metric

For each test pair `(x, y)`, exactly **2 candidates**:

| candidate | score | label |
|---|---|---|
| `sim(enc_anchor(x), enc_positive(y))` | forward score | 1 |
| `sim(enc_anchor(x), enc_positive(x))` | reverse score | 0 |

**AUC** — fraction of pairs where forward score > reverse score (ties = 0.5). Equivalent to P@1 here since it is always a binary decision.

**P@1** — same value (1 positive vs 1 negative).

Chance level = 0.5.

## Observations

**`followupqg` and `multiwoz_v24` learn direction very well** (AUC 0.998 and 0.976). The anchor and positive texts are structurally distinct — the model cleanly separates which side belongs in the positive tower.

**`aep_causal` barely learns direction** (AUC 0.556, barely above chance). Forward and reverse pairs score similarly (`mean_fwd=0.590` vs `mean_rev=0.562`). This makes sense: aep_causal pairs are long, overlapping documentation paragraphs — the model sees nearly identical content regardless of which text is fed to which tower.

**`qrecc` and `workflow`** fall in between (AUC 0.933 and 0.768), showing moderate directional discrimination.

## How to reproduce

```bash
# Full pipeline (mine + train + eval) in one command:
bash finetune_eval/train_all_reverse.sh
```

Or step by step:

```bash
# 1. Write reverse pairs for train + test (no GPU needed, ~1s per dataset)
uv run python finetune_eval/mine_hard_negatives_reverse.py --dataset all --splits train test

# 2. Train (results go to finetune_eval/results_reverse/)
bash finetune_eval/train_all_reverse.sh   # or train one dataset:
uv run python finetune_eval/train_finetune_reverse.py --dataset aep_causal --epochs 3

# 3. Evaluate (forward vs reverse, 2 candidates)
uv run python finetune_eval/evaluate_finetune_reverse.py --dataset all
```

## Training configuration

Identical to standard finetuning except:

| parameter | standard | reverse |
|---|---|---|
| hard negatives | K=4, kNN-mined from MiniLM | K=1, hard_neg = anchor text |
| mining step | ~15s on A100 (MiniLM kNN) | <1s (no encoding needed) |
| results dir | `finetune_eval/results/` | `finetune_eval/results_reverse/` |
| eval metric | AUC/P@1 vs 4 random negs + MRR/R@K in pool-1000 | AUC/P@1 vs 1 reverse neg only |

Everything else (backbone `bert-base-uncased`, CLS pooling, batch 32, lr 2e-5, OneCycleLR, early stopping patience 2) is unchanged.
