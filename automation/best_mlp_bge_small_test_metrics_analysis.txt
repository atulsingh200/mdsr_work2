10. KEY FINDINGS
--------------------------------------------------------------------------------
  1. OVERALL: 85.7% accuracy, 80.0% macro — improved micro over v6 but macro
     is similar. The gap between micro (0.857) and macro (0.800) is larger here
     than in v6, revealing distributional imbalance in the test set.

  2. MONOTONIC GAP TREND: Accuracy increases broadly with tier gap (0.69 macro
     at gap=1 to 1.00 at gap=13), confirming the model learns ordinal signal.
     Gap 10-11 are minor anomalies driven by T14 pairs with small test sets.

  3. T14 IS STILL A BLACK HOLE: 0.55 per-tier accuracy, 6+ bottom pairs involve
     T14. The AI Agents tier has sparse training data (max 1,300 for T6-T14) and
     its language is indistinguishable from adjacent tiers. Removing T14 pairs
     would substantially boost both micro and macro.

  4. T4-T5-T6 CLUSTER IS BROKEN: T4-T5 (0.35), T4-T6 (0.47) have max training
     data but perform near or below random. This is a content overlap problem, not
     a data problem. Profiles/audiences (T4), content authoring (T5), and channels
     (T6) are described together in AJO tutorials — the tier boundary is artificial.

  5. TRAINING DATA COUNT DOES NOT PREDICT ACCURACY: rho ≈ 0 for both all-pairs and
     adjacent-only. Same conclusion as v6.

  6. ADJACENT PAIRS ARE THE HARDEST: Macro 0.69 for adjacent vs 0.82 for
     non-adjacent. The model struggles most precisely where it needs to be sharpest.

  7. T7 (JOURNEYS CORE) IS SYSTEMATICALLY WEAK: Per-tier acc 0.78. Journey-building
     language permeates AJO documentation across all tiers. T7-T8 at 0.61 despite
     1,500 train samples reflects genuine semantic indistinguishability.

  8. T2 IS PERFECTLY SEPARABLE: Per-tier acc 0.98. Admin floor content has
     distinctive vocabulary (user management, permissions, access control) that
     is lexically unlike any other tier.

11. HONEST ANALYSIS — WHY IS THIS MODEL'S ACCURACY (0.8571) HIGHER THAN v6 (0.8226)?
    AND DID WE MAKE ANY MISTAKES?
--------------------------------------------------------------------------------

  SHORT ANSWER: The dataset is effectively the same. The model is identical.
  The accuracy difference comes from better training configuration — NOT from
  any real algorithmic or data improvement. And yes, there are real concerns.

  ── WHAT IS ACTUALLY DIFFERENT ──────────────────────────────────────────────

  Both models:
    - Same model architecture: 2x BGE-small-en-v1.5 (untied) + MLP [512,128]
    - Same hyperparameters: 3 epochs, lr_encoder=2e-5, lr_head=1e-3, batch=32
    - Same per-pair train counts: T1-T2=112, T1-T3=602, ... (verified identical)
    - Same total sizes: train=110,775, val=6,004, test=6,004

  Only best_mlp_bge_small specifies:
    - warmup_frac = 0.10   (10% of steps used for linear LR warm-up)
    - weight_decay = 0.01  (L2 regularization)
    - grad_clip = 1.0      (gradient clipping)
    - bf16 = True          (bfloat16 mixed precision)
    - seed = 42            (fixed random seed)
    - max_seq_len = 524    (auto-detected from data scan; v6 may have used 512)

  The v6 report does not state whether these were used. If v6 trained without
  warmup, weight decay, or gradient clipping, the optimizer would be less
  stable — especially for fine-tuning a pretrained encoder where the early steps
  can destroy pretrained representations with too-large gradient updates.

  ── WHAT ACTUALLY IMPROVED vs DEGRADED ──────────────────────────────────────

  Adjacent tier-pairs (the hardest, most important metric):
    v6  adj micro = 0.8401 → this model = 0.7824  DEGRADED  -5.8pp
    v6  adj macro = 0.7508 → this model = 0.6904  DEGRADED  -6.0pp

  Non-adjacent tier-pairs (easier pairs the model already handles well):
    v6  non-adj micro = 0.8201 → this model = 0.8680  IMPROVED  +4.8pp
    v6  non-adj macro = 0.8249 → this model = 0.8174  ESSENTIALLY SAME  -0.8pp

  Overall micro improved (+3.5pp) but ONLY because the large-volume non-adjacent
  pairs got better and they dominate the weighted count. On the core task —
  distinguishing adjacent tiers — this model is WORSE than v6.

  Per-pair regressions (adjacent, reliable n):
    T4-T5:   v6 0.5000 → now 0.3500  (-15pp, n=40)
    T5-T6:   v6 0.9625 → now 0.7875  (-17.5pp, n=320) ← largest regression
    T8-T9:   v6 0.9074 → now 0.8148  (-9.3pp, n=108)
    T11-T12: v6 0.8958 → now 0.8333  (-6.3pp, n=48)

  Per-pair improvements (adjacent):
    T6-T7:   v6 0.8646 → now 0.9479  (+8.3pp, n=96)
    T7-T8:   v6 0.4074 → now 0.6111  (+20.4pp, n=54)
    T10-T11: v6 0.5417 → now 0.7917  (+25.0pp, n=24)
    T12-T13: v6 0.5625 → now 1.0000  (+43.8pp, n=16)
    T14-T15: v6 0.7857 → now 0.9286  (+14.3pp, n=14)

  This whack-a-mole pattern — some pairs improve while others degrade — is
  exactly what v6 showed vs v5. The model does not genuinely improve on all
  adjacent pairs; it redistributes performance across them.

  ── REAL MISTAKES AND CONCERNS ───────────────────────────────────────────────

  1. THE CORE PROBLEM: THE TWO RESULTS ARE NOT MEANINGFULLY COMPARABLE.
     The v6 report explicitly calls its data "sentence-based data (data_v6_sent)".
     This run uses "aep_causal_classification" — but the per-pair train counts are
     BYTE-FOR-BYTE IDENTICAL (verified). Either (a) the datasets are literally
     the same files under different directory names, or (b) they were generated
     by the same pipeline with the same settings and the text lengths match.
     Either way: if the data is the same and the model is the same, the ONLY
     explanation for the accuracy difference is training-config variation.
     This should be verified: run diff or md5 on the two datasets.

  2. THE ACCURACY GAIN IS MISLEADING AS "BETTER".
     Overall micro went up (+3.5pp) but adjacent macro went DOWN (-6.0pp).
     The overall number improved because the model got better at non-adjacent
     pairs — the easier task — while getting worse at adjacent pairs, which is
     where the actual challenge lies. Reporting "85.7% > 82.3%" as an improvement
     without qualification overstates the progress.

  3. OVERFITTING IS SEVERE AND GETTING WORSE.
     Train loss at epoch 3 is 0.0172 while val loss is 0.8747 — a 51× gap.
     In the AEP companion run, the ratio was 26×. This model is memorizing
     training pairs, not learning generalizable tier signals. Val accuracy still
     rises (0.87 → 0.89) because the task's difficulty level allows the memorized
     patterns to transfer, but this is fragile. The encoder has essentially been
     fine-tuned into a lookup table for seen (doc, tier) combinations.

  4. TRAIN/TEST CONTAMINATION RISK.
     Both train and test contain pairs formed from the same document pool.
     Split is at chunk_tier level — meaning the same document chunk can appear
     in train for one tier-pair (e.g., T5-T6) and in test for a different pair
     (e.g., T5-T7). After 3 epochs of fine-tuning, the encoder has seen the
     actual text of chunks that appear in the test set, just in different pairings.
     This inflates test accuracy — the encoder recognizes familiar text and
     assigns it a tier embedding it learned during training. The true generalization
     performance to unseen AJO documents is likely lower than 85.7%.

  5. T5-T6 REGRESSED BADLY ON n=320 — NOT A SMALL-SAMPLE FLUKE.
     Going from 0.9625 to 0.7875 on 320 test samples is a genuine regression,
     not statistical noise. T5-T6 (Content authoring foundations vs Channels +
     campaigns) was one of the strongest pairs in v6 and is now merely average.
     Something about the training configuration change disrupted this pair's
     learned boundary.

  6. T1-T2 AND T13-T14 AT 0.00 LOOK ALARMING BUT ARE NOISE.
     T1-T2 has n=2; both predictions were wrong. T13-T14 has n=4. These numbers
     (0 of 2, 0 of 4 correct) are not informative about the model. Comparing
     v6's "T1-T2 = 1.00" to this model's "T1-T2 = 0.00" is comparing 2 correct
     vs 2 incorrect flips of a coin — ignore both numbers.

  ── WHAT TO DO ────────────────────────────────────────────────────────────────

  (a) Verify the datasets: run md5sum on directional_test.jsonl for both
      aep_causal_classification and data_v6_sent. If they match, the 0.8226→0.8571
      gap is purely a training-config artifact and the v6 report should be updated.

  (b) Focus on adjacent-pair macro as the primary metric, not overall micro.
      This model's adjacent macro (0.69) is WORSE than v6 (0.75). Overall micro
      improvements driven by large non-adjacent pairs are not meaningful progress.

  (c) Add early stopping on val_loss, not val_acc. The model is overfitting hard
      by epoch 3. Stopping at epoch 1 (val_loss=0.72) might give better
      calibration even if val_acc is slightly lower.

  (d) Use a held-out document set for test — documents whose chunks never appear
      in any training pair. The current split cannot guarantee this. Without it,
      the test accuracy is an optimistic upper bound.

    comparison against some other checkpoint, not against v6's full results.

13. SAMPLE PAIRS — CLOSE TIERS (hard) vs DISTANT TIERS (easy)
--------------------------------------------------------------------------------
  Core illustration of the gap-vs-accuracy finding (Section 4). When two
  segments come from ADJACENT tiers (gap=1), their documentation vocabulary
  overlaps heavily and the model is near random. When they come from DISTANT
  tiers (large gap), the vocabularies are disjoint and the model is near perfect.
  All examples are verbatim rows from directional_test.jsonl.

  ===== CLOSE TIERS (gap = 1) — model struggles =====

  [A] T4 vs T5   pair acc = 0.35  (worst reliable pair)   label = 1
      text_1 (T4, Profiles/audiences):
        "...I've received the email. Let me click on the link. And here's my
         unsubscription page and the confirmation page as well..."
      text_2 (T5, Content authoring):
        "...let's look for a profile attribute that we want to add. For example,
         the first name. We can also build conditional content..."
      WHY HARD: both discuss profile attributes inside message content; the
      T4/T5 boundary is barely reflected in the language.

  [B] T5 vs T6   pair acc = 0.79  (n=320, large regression)   label = 1
      text_1 (T5, Content authoring):

  ----- Accuracy vs gap (from Section 4), the one-line summary -----
    gap=1  -> macro 0.69   (CLOSE: hardest; T4-T5=0.35, T7-T8=0.61)
    gap=3  -> macro 0.79
    gap=8  -> macro 0.94
    gap=13 -> macro 1.00   (DISTANT: easiest)

  TAKEAWAY: difficulty is inversely proportional to tier distance. Adjacent
  tiers share near-identical vocabulary (acc 0.35-0.79 despite 1,500 train
  samples); distant tiers have disjoint vocabulary (acc -> 1.00). The bottleneck
  is semantic separability of neighbouring tiers, not data volume.
